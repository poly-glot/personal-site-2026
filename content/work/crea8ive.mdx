<Chapter label="The craft of 2007" title="Polish before CSS3." lede="In 2007 there were no rounded corners in CSS, no smartphones to design for, and Internet Explorer 6 was still everywhere. A polished site meant images, careful markup and a few well-chosen jQuery plugins.">
<Facts>
  <Fact k="Markup">Every page declared XHTML 1.0 Strict, the standard that serious front-end work aimed for at the time.</Fact>
  <Fact k="Corners">The rounded boxes are background images, a cap at the top and a strip that repeats down the side, years before border-radius worked everywhere.</Fact>
  <Fact k="IE6">Internet Explorer 6 couldn't show transparent PNGs, so a script patched each one. It, and separate stylesheets for IE6 and IE7, loaded only for those browsers.</Fact>
  <Fact k="Slideshows">jQuery Cycle runs the home showcase, the portfolio galleries and the testimonials.</Fact>
  <Fact k="Lightbox">prettyPhoto opens portfolio work full size without leaving the page.</Fact>
  <Fact k="Navigation">Superfish dropdown menus, tipTip tooltips and a smooth scroll back to the top.</Fact>
</Facts>
</Chapter>

<Chapter label="Content architecture" title="Four templates, 52 pages." lede="Each page had one job: sell, show, explain or help the site be found. Behind them, four templates for packages, portfolios, case studies and services did most of the work, filled from data.">
<ContentMap />
<Facts>
  <Fact k="Data">Packages and portfolio pieces live in data files, so a new package or a new logo is a data change, not a new page.</Fact>
  <Fact k="Components">The header, footer, offers, testimonials and top ten reasons are shared pieces, reused across pages.</Fact>
  <Fact k="Addresses">One script answers every address and picks the page from it, so every page has a readable address, like `/pages/logo_design`.</Fact>
  <Fact k="Weight">Each page loads only what it needs. The portfolio script, for instance, loads only on portfolio pages.</Fact>
</Facts>
</Chapter>

<Chapter label="Search" title="Built to be found." lede="Search was how a logo studio met its customers, and search engines of the day rewarded pages written around the phrases people typed.">
<List>
  <Item title="A page for every search.">The 23 case studies are landing pages, each named for a phrase customers searched for: free logo design, retro, corporate, web 2.0, professional logo designer.</Item>
  <Item title="Links that name the phrase.">Each case study links its phrase back to the home page, so the link itself says what the page is about. That was the link-building advice of the time.</Item>
  <Item title="Tags for every page.">Every page carries keywords and a description aimed at logo design searches, down to "Custom Logo Design just $99".</Item>
  <Item title="A map for crawlers.">An HTML sitemap with 97 links lets a search engine reach every page from one place.</Item>
  <Item title="A logo search engines can read.">The logo is an image laid over the studio's name, so crawlers still read "Crea8ivedesign.com".</Item>
</List>
</Chapter>

<Chapter label="Looking back" title="What aged, and what didn't." lede="Seen from today, the site shows which search habits lasted and which didn't.">
<List>
  <Item title="One title for every page.">The page class could give each page its own title, but no page does, so all 52 share one. The case studies would have ranked better with their own.</Item>
  <Item title="Keyword tags stopped counting.">Google said in 2009 that it ignores the keywords tag. Repeating one phrase in links now reads as stuffing, not relevance.</Item>
  <Item title="Structure still wins.">Readable addresses, a page per topic and a sitemap are still how a site gets found.</Item>
</List>
</Chapter>
