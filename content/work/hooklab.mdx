<Chapter label="The challenge" title="Make webhook integrations robust and reliable." lede="Webhooks are where integrations fail quietly. You hand Stripe or GitHub a URL and only find out what was sent when something downstream breaks. HookLab had to show every request and let you script the reply, and a scripted reply is someone else's code running on my server.">
<Rows>
  <Row title="See what was sent">Every request is kept with its headers, body, query and the reply it got, so a broken integration can be read, not guessed.</Row>
  <Row title="Reply with code">A fixed reply only goes so far. A short JavaScript function lets the endpoint answer the way the real service would.</Row>
  <Row title="Trust no script">Every script comes from someone I've never met. It must not reach the network, the disk or my secrets, however it is written.</Row>
  <Row title="Open to anyone">Guests can try it without an account, so limits had to exist on the first day, not after the first abuse.</Row>
</Rows>
</Chapter>

<Chapter label="The trust boundary" title="Split the product where the danger is." lede="Firebase does the ordinary parts: sign-in, storage and hosting. A small Deno server on Cloud Run does the one dangerous job: receive the webhook, run the script and log the result.">
<TrustBoundary />
<Facts>
  <Fact k="Hosting">Firebase Hosting serves the React app and passes `/w/*` and `/api/*` to Cloud Run.</Fact>
  <Fact k="Sign-in">Firebase Auth: Google, or a guest with seeded data.</Fact>
  <Fact k="Data">Firestore holds users, endpoints and execution logs.</Fact>
  <Fact k="Receiver">Deno and Hono on Cloud Run. `/w/{id}` accepts any method from anyone.</Fact>
  <Fact k="Deploy">Terraform for both sides, and CI through Workload Identity Federation.</Fact>
</Facts>
</Chapter>

<Chapter label="The sandbox" title="Each script runs with nothing." lede="Each script runs in its own Deno Worker. The runtime revokes its permissions, so the limits don't depend on my code being right.">
<Split>
<Facts>
  <Fact k="Network">Denied</Fact>
  <Fact k="Files">Read and write denied</Fact>
  <Fact k="Environment">Denied</Fact>
  <Fact k="Processes">Subprocesses denied</Fact>
  <Fact k="Native">Native calls denied</Fact>

<Facts>
  <Fact k="Time">5 seconds inside the worker, and the server ends it at 10. Then the endpoint sends its default reply.</Fact>
  <Fact k="Reply size">1 MB at most</Fact>

  <Fact k="Guests">3 endpoints, 100 runs a day</Fact>

<Chapter label="The evidence" title="Every claim is in the repository." lede="Security that only lives in a design document doesn't count. Each of these can be checked in the code or the history.">
<List>
  <Item title="Rules deny by default.">Firestore allows nothing unless a rule says so, scopes every endpoint and log to its owner, and lets only the backend write execution logs. The rules have their own tests against the emulator.</Item>
  <Item title="No key to leak.">CI deploys through Workload Identity Federation, so there is no service account key anywhere.</Item>
  <Item title="Fixes stay in the history.">Two later commits closed an insecure direct object reference and guarded the reporting chat's SQL check against prompt injection. Both have tests and neither was squashed.</Item>
  <Item title="Headers set at the edge.">Firebase Hosting adds nosniff, frame denial and a permissions policy that turns off the camera, microphone and location.</Item>
</List>
</Chapter>

<Chapter label="The limits" title="Where it stops today." lede="Each limit is a known trade, with the next step already named.">
<List>
  <Item title="One process, not one machine.">A Worker shares a process with the server. Revoked permissions stop a script reaching out, not burning CPU until the time limit. A busier service would give each run its own isolate or container, and pay for it.</Item>
  <Item title="Polling, not listening.">The inspector checks for new requests rather than being told. Fine for one developer watching a test, wasteful for a team watching live traffic.</Item>
</List>
</Chapter>
