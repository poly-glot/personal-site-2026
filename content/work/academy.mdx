<Chapter label="The prototype" title="Every page started as plain HTML." lede="I built those 26 pages in plain HTML and CSS before writing any WordPress, and treated them as final. The WordPress theme had to reproduce them, and any design change went into the prototype first.">
<Facts>
  <Fact k="Why first">The prototype runs on its own with Python's built-in web server, so anyone can review the design in a browser without a database or WordPress. The WordPress build then had one fixed target to match.</Fact>
  <Fact k="Same stylesheets">The theme copies the prototype's 33 CSS files byte for byte. A file comparison of the two folders finds no difference.</Fact>
  <Fact k="Same pages">In WordPress the 26 pages become 13 pages, the certificate list, 5 certificates, 6 news posts and the page-not-found template.</Fact>
</Facts>
</Chapter>

<Chapter label="The content model" title="The copy comes from the content model." lede="The prototype fixed the page structure, but an editor still had to change prices, courses and people without a developer. So the theme holds the structure, and the copy lives in fields described in YAML, a plain text format. Only a few labels, such as the contact form's, stay in the templates.">
<Facts>
  <Fact k="Model">Five YAML files describe two content types, certificate and person, a Site settings page and 18 groups of fields. The platform's yacf plugin reads them and builds the edit screens.</Fact>
  <Fact k="A certificate">Its fields match the facts list a learner reads: course code, level, category, duration, assessment and price. One more field decides whether it shows as a card or a link on the certification page.</Fact>
  <Fact k="Seed">The seed is one PHP script of 1,425 lines. It fills the fields and builds the 13 pages, 10 people, 5 certificates, 6 news posts, 7 menus and 24 images, and deletes WordPress's sample content.</Fact>
  <Fact k="Safe to rerun">The seed looks each post up by its slug, the last part of its address, and updates it if it exists. Menus change only the items that moved or point somewhere new, and the seed rebuilds an image only when the image sizes or WebP support change.</Fact>
  <Fact k="On each deploy">GitHub Actions deploys the site to Cloud Run, Google's service for running containers, then runs the seed as a job and waits for it. If the seed fails, the run stops before it updates Firebase Hosting, which serves the public address. By then Cloud Run is already serving the new image.</Fact>
  <Fact k="Platform">A base image shared with five other client sites holds WordPress and the yacf plugin. This repository holds the theme, the model and the seed.</Fact>
</Facts>
</Chapter>

<Chapter label="The front end" title="The theme keeps the prototype's rules." lede="The content model fills the pages, and WordPress adds its own styles and scripts to them. I switched off its styles, joined the prototype's 33 stylesheets into one file and wrote no JavaScript for the theme, as the prototype had none.">

<Facts>
  <Fact k="Styles">The theme switches off WordPress's block and global styles. When the server image is built, a build step joins the 33 CSS files into one `main.css`, in the order development loads them, so the rules apply in the same order in both.</Fact>
  <Fact k="Weight">The stylesheet is 43,083 bytes, and a browser downloads it compressed to 7,113 bytes.</Fact>
  <Fact k="Tabs">The tabs on the About page are links to `#founding` and `#staff`. The stylesheet shows the panel the address points to, and the first panel when it points to neither.</Fact>
  <Fact k="Images">WordPress saves each uploaded JPEG as WebP, a smaller format, at its own size and at smaller sizes for smaller screens. The home photograph is 639,810 bytes as a JPEG and 61,172 bytes as a WebP 1,376 pixels wide. The news photos load only when they scroll into view.</Fact>
  <Fact k="Contrast">The colours live in one file of values that every page shares. The palette's lightest grey text on its pale blue tint measures 4.61:1, above the 4.5:1 that level AA of the web accessibility guidelines (WCAG) asks of body text.</Fact>
</Facts>

<Chapter label="The limits" title="Where it stops today." lede="The pages read like a working site, but Academy is a demonstration, so the steps that would take money or personal data end at a message saying so. A few gaps belong to the build itself.">
<List>
  <Item title="Nothing can be bought.">Buy this certificate and Join now end at the enquiry form, and Register now opens the My Academy sign-in, which says no accounts exist. A real launch would need a checkout and member accounts.</Item>
  <Item title="The forms send nothing.">The contact form submits to its own page and shows a thank-you that says the message went nowhere. A real site needs somewhere for the message to go.</Item>
  <Item title="Screen-reader testing is still to do.">The accessibility statement aims for WCAG 2.2 AA. It also says the site has not yet been tested with a full range of screen readers or with disabled users.</Item>
  <Item title="No checks run before a deploy.">The pipeline builds and deploys. Nothing in it validates the pages or compares the theme's CSS with the prototype's, so nothing stops a deploy if the two copies drift apart.</Item>
  <Item title="WordPress still adds scripts.">The theme ships none, but WordPress core adds 3 small scripts to every page I checked: two for emoji and one that tells the browser which links to load ahead. I would switch the emoji ones off the way I switched off the block styles.</Item>
</List>
