<Chapter label="The decision" title="Content came first and WordPress came last." lede="Only one part of that brief needs a content management system (CMS), the software staff use to update a site: letting staff change the words. So the work went in five steps, and WordPress was the last of them.">
<BuildSteps />
<Facts>
  <Fact k="Why this order">Each decision is made where changing it costs least: a page title in the brief, a colour in the design tokens, a layout in the static pages. The first three steps use nothing from WordPress, so the theme had one fixed target.</Fact>
  <Fact k="The same HTML">The theme prints the fields into the same HTML and copies the 33 stylesheet files unchanged. Comparing the two folders file by file finds no difference.</Fact>
  <Fact k="Repeated">[Wealth](/work/wealth/), [Halveron](/work/halveron/) and [Boxes](/work/boxes/) were built the same way, static pages first.</Fact>
</Facts>

<Chapter label="Content architecture" title="The brief fixed 26 pages, three content types and the navigation." lede="Content architecture is what a site holds and how it is organised. It was written down first, so every page had an address and its sections before anyone built it.">
<SiteMap />
<Facts>
  <Fact k="Content types">Certificates, people and news articles are each entered as items of their own. A certificate and an article get a page each, and a person appears on About.</Fact>

<Chapter label="Editorial control" title="An editor changes a page without a developer." lede="Components settle how a page looks. What a page says keeps changing after launch, so each word that might change is kept in a named field, and the components print whatever the fields hold. The content model is the list of those fields.">
<ContentModel />

<Facts>
  <Fact k="Model">125 fields in 18 groups, written in five short files of YAML, a plain text format. The platform reads those files and builds the edit screens, so the model is reviewed like code.</Fact>
  <Fact k="Entered once">A certificate, a person and an article are each entered once. A person's card appears on About, and an article names that person as its author.</Fact>
  <Fact k="No formatting">Each field is plain text, a choice from a list, an image, an email address or a link to another item. None accepts free formatting, so an editor cannot change a font, a colour or a layout by accident.</Fact>
  <Fact k="Guidance">Where an editor might guess, the field says what it expects: ‘Bio (about 40 words)’ or ‘Separate paragraphs with a blank line’.</Fact>
</Facts>

<Chapter label="Accessibility and speed" title="Contrast and weight were settled once, for all 26 pages." lede="Because editors enter words and little else, the decisions that make a page usable sit in the components and the 53 design tokens, where each was made once.">
<Figures>
  <Figure src="/img/work/academy/skip-link.webp" w={1600} h={1000} alt="The top of the home page after one press of the Tab key: a Skip to main content link over the logo, inside a blue ring with a white edge." title="Skip link">Press Tab once, and the first thing the keyboard reaches is ‘Skip to main content’.</Figure>

</Figures>
<Facts>
  <Fact k="Contrast">The web accessibility guidelines (WCAG) ask for 4.5 to 1 between body text and its background. I measured 13 pairs of colours from the tokens, and the lowest is 4.61 to 1.</Fact>
  <Fact k="Keyboard">Buttons are at least 44 pixels tall. The focus ring is brand blue with a white edge, because blue alone measures 2.14 to 1 on the navy bands.</Fact>
</Facts>

<Chapter label="The build" title="The site accepts very little, and the server cannot be changed in place." lede="A brochure site needs almost nothing from its visitors, so it accepts almost nothing, both in the code and in the way it is hosted.">
<ChangeRoutes />
<Facts>
  <Fact k="A sealed server">The site runs as a container on Cloud Run, Google's service for running packaged software. In production WordPress cannot install a plugin, edit a theme file or update itself.</Fact>
  <Fact k="Escaped output">Escaping makes harmless any characters a browser could read as code. The theme does it in 193 places.</Fact>
  <Fact k="Patching">WordPress and PHP come from a base image that six sites share. A security fix is a one-line change: the latest commit moves to a base image that fixes two published PHP vulnerabilities.</Fact>
</Facts>
</Chapter>

<Chapter label="The limits" title="Which rules have a check today." lede="I trust a rule more when something checks it than when it depends on someone remembering. Two of the rules above are enforced by the way the site is built. The rest are not checked yet.">
<List>
  <Item title="Two rules are enforced.">The platform lets a change in only as a new image built from the repository, and the content model offers editors no formatting.</Item>
  <Item title="Nothing compares the two sets of stylesheets.">The static pages and the theme match today. No step in the pipeline compares them or tests a page, so a careless change could separate them unnoticed.</Item>
  <Item title="Accessibility has no automatic test.">The contrast figures are mine, measured by hand, and no tool checks a page before a deploy. The site aims for level AA of WCAG 2.2. It has not been tested with screen readers or by disabled people, and its own accessibility statement says so.</Item>
  <Item title="Each deploy puts the starting content back.">A script called the seed fills the site with its starting content on every deploy, which suits a demonstration. On a live site it would undo an editor's work, so the seed would run once, at launch.</Item>
  <Item title="Hardening and the forms are unfinished.">The site sends no content security policy, a header that tells the browser which scripts to trust, and WordPress still announces its version. Join now, Buy this certificate and the contact form end at a message saying this is a demonstration.</Item>
</List>
