<Facts>
  <Fact k="The rule">A 19-line file in the campaign's own folder. Guardian if any answer points to giving instead of running ('I'd rather cheer than run', 'Money' or 'Five minutes a month'), then Coalition if the visitor brings others or wants a team total, then Solo. Three tests pin that order.</Fact>
  <Fact k="One value">Each click works out the recommendation again and selects it.</Fact>
  <Fact k="Screen readers">Each answer is a toggle button that reports whether it is pressed. The page announces the recommendation to screen readers when it changes, without cutting in on what they are reading.</Fact>
  <Fact k="Nothing kept">The answers live in the page's memory. There is no cookie, no analytics and no server to send them to, so a reload starts the quiz again.</Fact>
</Facts>

<Facts>
  <Fact k="A campaign">A folder of copy, settings and a media list, plus an optional folder for the code it owns: a logo, a font, a quiz rule and a theme.</Fact>
  <Fact k="Languages">Each language is a folder. A new one brings its own routes, hreflang links (the tags that point search engines at a translation) and pages in the accessibility checks, with no code change.</Fact>
  <Fact k="Registry">Each campaign's settings sit in a registry, a short list in the code. A campaign folder missing from it fails the build, and the error says where to add it.</Fact>
  <Fact k="Parallel builds">Next.js builds the pages in parallel, so each page keeps its own record of its campaign in React's `cache()`. One shared variable would let one page pick up another's campaign.</Fact>
  <Fact k="Boundaries">A lint rule stops campaign code importing the app's internals, so a campaign plugs in through the registry alone.</Fact>
  <Fact k="Paws & Pace">10 files of its own, plus its registry entries. Its brand colour is two CSS custom properties, and it brings its own font and quiz rule and renames the options Stride, Pack and Patron.</Fact>
</Facts>
</Chapter>

<Chapter label="The checks" title="Each rule names the check that catches it." lede="Each new campaign or language adds pages that must meet WCAG 2.2 AA, the web's accessibility guidelines: 8 pages so far. The rulebook, CLAUDE.md, written for people and for coding agents, names the check that catches each rule. The build server runs the automated ones and won't deploy past a failure.">
<List>
  <Item title="Types, lint and tests on each commit.">`npm run check` runs in the repository's pre-commit hook and again on the build server. Lint, an automatic code checker, treats its accessibility rules as errors. Tests fail on a screen-reader label typed into the code instead of taken from the translations, a stylesheet that hides the focus outline, a font size in pixels, a skipped heading level, or section ids that differ between languages.</Item>
  <Item title="16 browser audits.">axe-core, an automated accessibility scanner, opens each of the 8 pages at a desktop and a phone width, scrolls through it, and fails the run on any serious or critical problem. A scanner finds only what a machine can measure, which is part of WCAG.</Item>
  <Item title="12 journeys.">Scripted visits click, press keys and measure the page, most of them on the two English home pages: text spacing raised to the WCAG overrides with no text spilling out of its section, contrast read from the pixels behind the hero heading, and no control hidden under another. That last one exists because the logo once covered the motion button at 390px, and axe missed it.</Item>
  <Item title="One check stays manual.">The rulebook's definition of done includes a five-minute pass by keyboard and with VoiceOver, Apple's screen reader, with no script behind it.</Item>
</List>
<Facts>
  <Fact k="One switch">Motion is one of those rules. Every animation and scroll effect reads one flag, `motionPaused`, so one setting stops them all.</Fact>
  <Fact k="System first">The flag follows the reduce-motion setting in the visitor's operating system, live. The Play motion and Stop motion button in the header overrides it until that setting changes.</Fact>
  <Fact k="Paused">Counters and reveals show their finished state, and on a desktop the sticky cub scene shrinks from three screens of scrolling to one still screen.</Fact>
  <Fact k="Tested">4 unit tests cover the switch, including a stored choice that expires when the system setting changes. The `motionControl` journey presses the header button and checks the page pauses and resumes.</Fact>
</Facts>
</Chapter>

<Chapter label="The limits" title="Where it stops today." lede="The checks cover the page a visitor sees. The campaign behind it stops at the sign-up, and the README, the rulebook and the published accessibility statement list most of these gaps themselves.">
<List>
  <Item title="It stops at the sign-up.">Each city links to a placeholder address, and Privacy, Terms and Contact in the footer are plain text. There is no registration, payment or fundraising page, although the copy describes them. To run it for real, I would put a sign-up service behind the city links.</Item>
  <Item title="The opening video is heavy.">The desktop hero clip in AV1, a newer video format, is more than 9 MB. A phone that can't play AV1 downloads a portrait file of more than 7 MB. Each image slot holds one file, sized for the largest screen that shows it, so a phone downloads the desktop picture. The rulebook names the fix for images, a build step that writes smaller sizes, and I would encode smaller clips.</Item>
  <Item title="The statement lists its own gaps.">Gallery photos have no descriptions, copy over the hero photo may fall short of 4.5:1 contrast in some viewports, and the feature videos rely on YouTube's captions. I haven't yet checked the 320px width that 400% zoom produces.</Item>
</List>
</Chapter>

<Chapter label="The outcome" title="What carried forward." lede="Three lessons from the build, and figures you can check in the repository.">
<Split>
<List>
  <Item title="Let one answer drive the page.">Five questions reduce to one value, and the sections below the quiz read it, so a visitor reads about one way in rather than comparing three.</Item>
  <Item title="Add the second campaign early.">Building Paws & Pace on the first day showed which parts belong to a campaign and which to the platform. The campaign's share came to 10 files.</Item>
  <Item title="Tie each rule to a check.">When a rule names an automated check, breaking it stops the deploy, so the rulebook stays true as the page changes.</Item>
</List>
