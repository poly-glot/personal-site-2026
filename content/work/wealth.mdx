<Chapter label="The content model" title="WordPress stores each link on one side." lede="Those links come from fields, the boxes an editor fills in for each record. A strategy lists the people who manage it, and an insight names its author. A person's record stores neither, so the theme works out what each person manages and what they last wrote, and the two pages cannot disagree.">
<Facts>
  <Fact k="Model">Six YAML files, a plain text format, define three content types (strategy, person and enquiry), a Site settings page and 65 fields in 12 groups. The platform's yacf plugin reads them and builds the edit screens.</Fact>
  <Fact k="A strategy">14 fields, from its tint and tagline to How we invest, Key risks, Questions investors ask and Managed by. The theme builds the page from six template parts, and the tint colours the band at the top of the page.</Fact>
  <Fact k="Managed by">An ordered link to one or more people. The strategy page prints the names, in that order, as a sentence of links.</Fact>
  <Fact k="Manages">The person page goes through the four strategies and finds the person's place in each Managed by list, so the strategies where they are named first come first. Daniel Okafor's page lists European Quality Growth, where he is the only name, before UK Equity Income, where Eleanor Whitcombe is named first.</Fact>
  <Fact k="Latest insight">The person page asks for the newest insight whose author field points at that person. The insights list fetches all its authors in one trip to the database, instead of one per insight.</Fact>
  <Fact k="One relation">At first a person also had a Manages field of their own, so one fact lived on two records and an editor could change one and forget the other. Commit 4802e49 on 2 October 2026 removed it, and the seed deletes the old value.</Fact>
</Facts>
</Chapter>

<Facts>
  <Fact k="Tabs">Each tab is a link to its panel's address. The stylesheet shows the panel the address points to, using `:target` and `:has()`, and the first panel when it points to neither.</Fact>
  <Fact k="Questions">On each strategy page, the questions investors ask are native `<details>` elements, so they open and close without a script.</Fact>
  <Fact k="Menu">The menu button starts hidden. A 34-line script shows it, opens and closes the list, closes it on Escape and returns focus to the button. Without the script the six links wrap under the logo.</Fact>
  <Fact k="Motion">Each home screen ends in a chevron, a link to the next screen. The smooth scroll switches off for visitors who ask their system for reduced motion.</Fact>
  <Fact k="Basics">A link to skip past the menu, a 3px outline on whatever has keyboard focus, a label on every form field, and the current section marked in the menu for screen readers.</Fact>
  <Fact k="Weight">The theme adds one script of 895 bytes. The Docker build joins 30 CSS files into one stylesheet of 39,357 bytes, about 7 KB compressed.</Fact>
</Facts>
</Chapter>

<Chapter label="The enquiry" title="WordPress stores every enquiry as a private record." lede="The contact form also leans on the browser, which checks the required fields before the visitor can send them. Behind the form, I wrote the handler in about 40 lines of theme code instead of adding a form plugin. It saves each enquiry in WordPress, and the site sends no email.">
<List>
  <Item title="A token on the form.">WordPress checks a security token tied to the form, called a nonce, before it reads anything, and sends the visitor back if the token fails.</Item>
  <Item title="A trap for bots.">A hidden field called website stays empty for people. A bot that fills it sees the thank-you page, and the site stores nothing.</Item>
  <Item title="Only known answers.">The handler cleans every value and blanks any investor type outside the 6 listed choices. If the name, email, message or consent tick is missing, it sends the visitor back and saves nothing.</Item>
  <Item title="A list in wp-admin.">Enquiries are a content type the public cannot reach. In wp-admin, WordPress's editing screens, an editor sees each one under the sender's name and the time, with columns for organisation, email and investor type.</Item>
</List>
</Chapter>

<Chapter label="The platform" title="The repository rebuilds the whole site." lede="The handler is one small part of the theme. The theme runs on wp-base, a WordPress server image that five of my other sites also use, hosted on Cloud Run, Google's service for running packaged apps. This repository adds a prototype, a theme and a seed, built in that order.">
<Facts>
  <Fact k="Prototype">I built every page first in plain HTML and CSS: 26 pages and 4 shared pieces, such as the header and footer, in `static/`, with the 30 CSS files the theme ships.</Fact>
  <Fact k="Theme">On 1 October 2026 I ported those pages into a classic WordPress theme of 41 PHP files, 24 of them template parts.</Fact>
  <Fact k="Seed">A PHP script of 866 lines that writes the content into WordPress: 4 strategies, 6 people, 6 insights, 7 pages, 2 menus and 21 images. It also deletes WordPress's sample content.</Fact>
  <Fact k="Safe to rerun">The seed finds each post by its slug, the last part of its address, and updates it. It repairs a menu item only when its position or link has changed, and rebuilds an image only when the image sizes or WebP support change. Three fixes on 2 October 2026 added the menu and image rules.</Fact>
  <Fact k="On each deploy">A push to the main branch builds the image, deploys it to Cloud Run, then runs the seed as a job and waits for it. Only a successful seed lets the run redeploy Firebase Hosting, which serves the public address. The new image is already live by then, so a failed seed stops the run without rolling the site back.</Fact>
</Facts>
</Chapter>

<Chapter label="The limits" title="Where the site stops today." lede="The seed and the theme run the live site today. Wealth is a demonstration, so some gaps are deliberate, and others belong to the build.">
<List>
  <Item title="Nobody hears about an enquiry.">The thank-you text promises a reply within two working days, but a stored enquiry waits until someone opens wp-admin. The privacy notice also names an email service the code does not use. I would add a notification to the same handler.</Item>
  <Item title="The seed owns the content.">From the code, every deploy rewrites the seeded posts, fields and settings, so an edit made in wp-admin would last until the next push to main. I have not tested this on the live site. I would change the seed to fill in only what is missing.</Item>
  <Item title="The home menu opens behind the hero.">At 390 pixels wide, the open menu on the home page sits under the hero photograph. It works on the inner pages. I expect the fix is a stacking order that puts the open list above the photograph, but I have not tried it.</Item>
  <Item title="Documents and search are placeholders.">Each strategy lists a factsheet, a key information summary and a quarterly letter with no files, and tells screen readers so. A search results template exists, but no page shows a search box.</Item>
  <Item title="No checks before a deploy.">The repository has no tests and no HTML or accessibility checks. The seed job is the closest thing to a check, and it runs after the new image is already live.</Item>
</List>
